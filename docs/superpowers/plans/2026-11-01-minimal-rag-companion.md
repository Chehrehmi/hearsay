# Minimal RAG Companion — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the existing Hearsay multi-tab dashboard with a single-purpose, distraction-free RAG chatbot UI that demonstrates live hallucination detection and auto-correction on frontier models, evaluated Monday.

**Architecture:** Branch `feat/minimal-rag-companion` off `feat/adversarial-eval-react-ui`. Replace `App.tsx` shell with a minimal three-panel layout: left conversation history sidebar (localStorage-persisted), center chat thread, right collapsible inspector drawer. Add three backend endpoints: PDF upload, adversarial question bank, and multi-provider API key persistence. All verification logic (`HearsayEngine`, `TraceStore`, `DeBERTa-v3`) is reused as-is.

**Tech Stack:** React 18 + TypeScript + Tailwind CSS (Vite); FastAPI (Python 3.11); `pdfplumber` (primary PDF extraction) with `pypdf` fallback; SQLite via existing `TraceStore`; any OpenAI-compatible API (Gemini 2.5 Flash default).

**Spec:** `docs/superpowers/specs/2026-11-01-minimal-rag-companion-design.md`

## Global Constraints

- Zero mock data — all scores, latencies, and claim verdicts come from real `HearsayEngine` payloads.
- Strictly no emoji anywhere in the UI — labels, buttons, pills, toasts. SVG line-art icons only.
- Do not modify: `RAGCompanionView.tsx`, `SandboxView.tsx`, `AdversarialMatrixView.tsx`, `TraceExplorerView.tsx`, `AnalyticsView.tsx`, `TelemetryKpiBar.tsx`, `engine/`, `eval/`, `db/`, `tests/`.
- `contradiction_pct` = `(contradicted_claims / total_claims) * 100` — computed client-side only, no schema change.
- API key stored server-side in `.env` file via `POST /v1/settings`. Never returned to frontend after save.
- Drawer auto-opens on each new assistant message; collapses on `×`; clicking any previous assistant bubble refreshes drawer to that turn's trace.
- Re-answer loop delay: 500 ms so evaluator sees the original hallucinated response before auto-correction.

## Review Focus

1. **Empty PDF:** Uploading a zero-byte or image-only PDF — `POST /v1/rag/upload` must return 400 with a human-readable detail, not a 500.
2. **API key not set, live mode selected:** Chat should fail gracefully with an inline banner ("No API key configured — use Settings") rather than a crashed request.
3. **`total_claims = 0` from engine:** `contradiction_pct` division-by-zero guard on the client must show 0% and not throw.
4. **Re-answer loop with > 30% contradiction — second response also contradicts:** The UI must show the auto-corrected tag on the second response regardless; it must not loop again.
5. **Drawer click on user bubble (no verification):** Clicking a user message must not crash the drawer; it should stay showing the last assistant turn's trace.

  Implementation logic:
  1. Read bytes; if `len(bytes) == 0` raise `HTTPException(400, "Empty file")`.
